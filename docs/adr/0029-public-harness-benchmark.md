## 决策

Accepted · 2026-10-21。用户通过 grill-me 访谈确认：
日常已有项目修 bug、加小功能；同模型比较 niucode、mini-SWE-agent、DeepSeek Harness、Pi；
基础单 agent 与增强配置分轨；公开基准加自建简单案例；首轮 API 上限 ¥300。
完成标准是可信、可复现的基线，不要求 niucode 获胜。

1. 评测设施属于 engineering，放在 benchmarks/，不进入 agent/core。
2. 任务为公开的合成小仓库，注明来源、范围和限制。基础版本、需求、参考补丁、
   独立验收、错误修复样例全部公开；自建题运行时不给 agent 评分测试与参考补丁。
   外部 Polyglot 子集保留公开原始测试可见，参考解仍不进入运行工作区；单独报告协议差异。
3. 每次运行使用全新隔离容器和工作区，只开放受限模型网关。评分另起无外网容器，
   恢复原始测试与构建清单，只采纳候选源码。案例禁止新增外部依赖，需求须明确这一限制。
4. 模型统一 deepseek-flash、thinking enabled、high、8192 输出上限。
   框架保留原生提示词和工具协议；Messages/ChatCompletions 协议差异必须公开。
   服务别名无法锁定底层快照，记录日期、请求和返回模型标识，交错运行配对任务。
5. 基础轨关闭额外技能/插件/MCP/子 agent；增强轨提前冻结通用验证工作流及各框架可用的
   原生/官方示例委派能力。增强轨不是“每家最优配置”，不得如此宣传。
6. gateway 独立使用 niucode-auth 解析凭证。参赛容器只有本地占位凭证。
   请求前以全上下文容量和输出上限预留高峰费用，最终 usage 结算保守上界；
   无 usage、断连、超时、崩溃保留预留，日志损坏或写失败停止付费调用。
7. 各 harness 的事件/轨迹仍是对应会话的唯一持久事实。
   benchmark 的追加计费日志记录评测费用事实，不保存第二份可恢复会话或任务队列；
   配置、patch、评分与报告是独立评测产物，不能驱动会话重放副作用。
8. 成绩按任务集、轨道、版本分别报告。基础设施错误、超时、测试失败、未运行分开；
   模型自评 met 和进程退出 0 都不能替代独立验收。公开分母、重复次数、费用和逐题结果。
9. 无人工提示为自动评测主轨；日常运行中纠偏、恢复、终端实测另记，不由 headless 成绩代替。
10. M6 保持 active，M7 作为 planned 的后续阶段先建设评测设施；
    不以自动化 benchmark 关闭 M5/M6 真实终端 gate。

## 交付与限制

先用独立 dev 题调通适配，再冻结正式八题和外部公开基准实例。
任何正式题发生规格或评分修改，须改变任务集 hash 并作废受影响对比。
先跑小样本实测成本，再决定 ¥300 内重复数量。
八题只检验小范围代码修改，不代表大仓库、长上下文、多语言全面能力，也不是行业排行榜。
配置、案例与结果可公开交付；推送/发布到外部平台另按用户指令处理。
