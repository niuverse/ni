## 状态与目标

2026-10-21：用户已确认产品方向和完整日常结对闭环的范围，并要求代码 robust、clean，不引入 dirty hack。共享编辑、运行时输入、审批/取消、历史详情、文件版本冲突与任务证据已实现，进入 review。M6 为 active；M5 的 inline review 和 Ghostty blocked 状态保持，实机矩阵及慢终端长时间压力验收未完成。

目标：用户能在原生终端里持续输入、观察、纠偏、取消和审阅 agent 的工作，界面状态与实际执行记录一致。真实编码任务评测集另立后续里程碑；本轮包含功能回归和真实终端交互验收。

## 第二阶段：从 hello 刷屏故障到可持续结对

2026-10-21：用户在最新版本地 TUI 中输入 `hello`，回答之后出现大量文件清单。
以下保留故障诊断与实施验收契约。用户随后授权全部实施；实现与测试进展见 [TUI 升级验证](tui-upgrade-validation.md)，真实终端门槛继续独立跟踪。
原 M6 实机门槛继续有效，M6-010 文本布局完成不代表信息层次和审阅语义已通过验收。

### 已确认的问题

本地复现依据为会话 `1792569929010-3258034-0.jsonl`，只记录汇总，
不把含工作区文件正文的会话复制进公开测试或 benchmark。

| 观察 | 根因及影响 |
|---|---|
| `hello` 没有工具调用；前后快照各 394 个条目，条目完全相同 | 264 个条目有 digest，130 个无 digest；相同的未知条目不能证明文件变化，也不能证明内容未变 |
| 130 条文件清单被打印为 `workspace change · origin unknown` | `changes.rs::task_review` 只跳过 digest 非空且相等的条目；其余直接进入变化列表，把覆盖不全误当成变化 |
| 完成后仍不断输出，结尾有两次成功信息 | `live.rs` 打印全部 `review.summary`，随后 `tui.rs` 再打印 done；详情还重复拼接 summary 和 detail |
| 问候后提示 `No recorded command checks; unverified.` | 检查数为零时无条件生成提示，把没有执行检查和需要验证的修改混为一谈 |
| 单次问候日志 8,568,094 字节 | 两份快照各带 3,789,249 字节文件正文；无工具对话也承担完整采集与序列化开销 |

目前 `MAX_BYTES` 为 4 MiB，预算不足的文件留下无 digest 条目。
测试覆盖了大文件快照不完整，却没有覆盖“两份相同的不完整快照进入任务审阅”，
也没有从 TUI 的最终输出断言系统消息的数量。这是需要补齐的验收缺口。

### 目标体验与信息层次

默认界面保留原生 scrollback。主屏优先显示用户消息、模型回答、需要行动的异常；
运行状态留在活动区，已记录的详细证据从 Ctrl-O 打开。建议效果如下，耗时仅为示意：

```text
niucode ▸ hello
你好，有什么需要一起处理的？
✓ 完成 · 1.2s

niucode ▸ 修复解析器并运行测试
已修复空输入处理，并运行了解析器测试。
✓ 完成 · 2 个文件变化 · 1 条检查命令退出 0 · 12s
审阅覆盖不完整 · Ctrl-O 查看详情
```

第二个示例的检查状态仅表示实际命令退出码，不推导全部验收通过。
任务完成、文件变化、检查结果、覆盖范围分别判断：失败、取消、输出截断、
审批拒绝或证据缺失不能被绿色完成标记掩盖。

| 信息 | 默认位置与预算 |
|---|---|
| 启动信息 | 80 列下至多 2 行，包含项目、模型和当前权限模式；完整路径、auth 来源、预算和大 logo 不常驻，诊断从 `/status` 查看 |
| 用户消息与模型回答 | transcript 正文；不以系统消息预算截断用户需要的回答或代码 |
| 运行阶段、耗时、工具进度 | 活动区更新；连续成功工具操作合并计数，不把每次刷新追加到历史 |
| 任务结束 | 每个任务一次；80 列下系统收尾至多 3 个显示行，与文件数、路径长度、命令长度无关 |
| 错误、冲突、审批 | 错误保留可行动摘要及详情入口；审批独立展示具体操作和 diff，不受普通摘要预算裁掉关键授权信息 |
| 文件路径、累计 diff、命令全文、reasoning、token/cache、内部 ID | Ctrl-O 或 `/status`；按任务及调用定位，列表先行、按需展开；恢复后仍可查看已记录内容 |

窄窗口按同一字素布局换行或裁剪系统摘要；20/40 列收尾至多 5 个显示行。
没有副作用、没有已证实外部变化的对话不生成文件清单或“未执行检查”警告；
覆盖不足仍记录于详情，不宣称整个工作区未变化。真实修改后没执行检查则明确提示。
不增加模型意图分类请求，也不靠 `hello` 关键词特判决定是否采集或显示证据。

### 交付顺序与代码边界

| 顺序 | 卡片 | 交付与删除点 |
|---|---|---|
| P0 / 1 | M6-011 纠正审阅语义 | agent 投影区分已证实变化、可比较且未变、无法确认；覆盖不足独立记录。删除“未跳过即变化”的判定；已证实变化的归属另行判断 |
| P0 / 2 | M6-012 主屏收敛 | 修正收尾和启动信息层次，工具进度有界，完整记录进入详情；删除 live/tui 双重完成输出和无条件检查警告 |
| P1 / 3 | M6-013 呈现所有权 | agent 提供结构化审阅事实，CLI 统一决定文案与布局；主屏和详情消费同一投影，删除重复 summary/detail 文案拼装及视图冗余状态 |
| P1 / 4 | M6-014 证据采集成本 | 单独测量扫描、哈希、正文保存、序列化与回放成本，选择保留任务起点语义的正文去重方案；删除不必要的重复正文写入 |
| P1 / 5 | M6-015 输出与负载验收 | 建立可重放的输出预算与长期负载场景；汇总前面每卡的回归，并将真实终端复验交给 M6-009 |

011 → 012 为第一次可试用交付；013、014 随后分别收敛呈现和采集。
015 的 fixture 和测量从 011 开始积累，不等重构完成再补测试。
每次可试用交付记录源码状态及产物 hash，检查 PATH 实际命中的二进制，再提供体验步骤。

实现约束：

- `niucode-agent` 判断证据，不持有终端行宽、颜色或控件；结构化投影可在 011 引入必要部分，013 收敛全部消费者。
- CLI 沿用 Composer、text_layout、TerminalSession、runtime 命令/事件；一种状态只有一个呈现责任点，不新增通用 UI 框架或第二个事件循环。
- 详情/审批状态收敛时保留草稿、选择和滚动位置；Esc、Ctrl-C、resize、运行中消息遵守现有边界。批准与普通键入不能混淆。
- 事件日志仍是唯一持久事实。014 比较“引用已有事件正文”与“仅保存必要正文”等方案，明确历史 diff 覆盖及旧日志兼容；不先建外部快照数据库。
- 任务开始基线不得悄悄挪到首次写入。若改变持久字段或覆盖契约，实施前单独记录 ADR 和 decision 事件；此计划没有批准替换 ADR-0028。
- 保留 linear fallback；没有实机证据不切换默认渲染模式。

### 回归与测量标准

| 场景 | 必须验证 |
|---|---|
| hello + 脏仓库 + 130 个未知条目 | 0 个被证实变化、130 个覆盖未知；无工具的事实保留，主屏只有一次收尾，不打印逐文件误报 |
| 不完整枚举、二进制、大文件、模式变化 | 缺失条目不自动算增删；可比较 digest 或 mode 的真实变化不被隐藏，无法证明的内容仍为未知 |
| 原有 staged/unstaged/untracked + 工具写入 + 外部修改 | 起点为任务开始，真实外部变化可见但不归因 agent；index 不变；回放结论一致 |
| 1 / 100 / 1000 个变化文件，超长命令及路径 | 系统收尾行数不随规模增长；详情能定位全部已记录结果；正文不受摘要预算影响 |
| 无修改、修改无检查、检查非零、检查后继续修改 | 检查缺失/失败/过期分别显示；普通命令退出 0 不冒充整体验收通过 |
| 输出 length、网络错误、冲突、取消、日志写入失败 | 不显示正常完成；保留已记录内容、可行动原因和审阅入口，不丢失失败原因 |
| 运行中输入/排队/审批/详情 + resize | 无重复消息或尾部丢失，关闭详情恢复草稿与光标，取消不等待详情退出 |
| 100 轮无变化对话及 30 分钟慢输出 | 记录每轮日志增量、常驻内存、采集/回放时延及取消时延；输出队列有界 |

014 的初始性能验收目标：固定 394 文件 fixture，首次建立基线后，后续无变化轮次
的证据字节增量比现状降低至少 90%；另列首次采集成本，不用预热数字代替。
同机同 fixture 报告中位数/P95；100 轮后正常受控等待的 Ctrl-C 到停止输出 P95
不超过 250ms（不含操作系统不可中断 I/O）。实施结果已记录在 [TUI 第二阶段验证](tui-upgrade-validation.md)：证据增量下降 98.81%，任务结束 P95 124.9ms；输入框恢复 P95 350.28ms 独立报告。

测试使用 synthetic repo、scripted provider 与本地 PTY，不依赖付费模型或私人会话正文。
除了现有 workspace/fmt/clippy/dashboard 检查，断言应落在公开行为：屏幕行数、
任务结果、日志回放和 index 保留，而不是只检查新增类型或 ANSI 字符串。
真实 Linux/macOS、IME、复制、scrollback 与 tmux 继续由 M6-009 留证，PTY 不替代实机。

`benchmarks/evidence/2026-10-21-v1/` 与 `2026-10-21-truncation-fix/` 保持不变；
TUI 输出预算是独立交互回归，不能拿新表现回填原有模型 benchmark 成绩。

## 已确认的产品契约

| 方面 | 决定 |
|---|---|
| 形态 | 主会话使用终端原生 scrollback；保留自然选择复制、终端搜索；底部输入与状态区统一管理 |
| 输入 | 多行、粘贴、中文、长文本、历史和补全使用同一套编辑规则 |
| 运行中输入 | Enter 补充当前任务；下一次模型请求前生效；显示待接收/已接收；独立任务显式排队 |
| Reasoning | 默认收起，通过详情查看完整已记录内容；显示真实状态和耗时，不生成虚构进展 |
| 代码审阅 | 执行时文件改动简报，结束后本轮累计 diff；审批仍展示具体操作的 diff |
| 并发编辑 | 默认共享工作区，支持用户同步编辑；冲突显式处理，未知来源不归因给 agent |
| 平台 | Linux + macOS，Ghostty/Kitty/WezTerm/代表性系统终端，直连与 tmux 分别验收 |
| 完成依据 | 改动和验证结果引用事件；通过、失败、取消、未验证分别呈现 |

## 实施前代码审计基线（历史）

| 当前证据 | 实施影响 |
|---|---|
| `crates/niucode-cli/src/editor.rs` 的 Paste 将换行替换为空格；`inline.rs` 独立实现编辑、历史、候选与宽度处理 | 先统一编辑状态和布局计算，再替换渲染；不在两套实现里各补一遍 |
| `inline.rs` 长行按字符数截断，光标另按显示宽度定位 | 光标、裁剪、换行、鼠标定位必须使用同一布局结果 |
| `tui.rs` 先阻塞 read_line，再 await run_with_history；observer 直接交错写 stdout/stderr | 运行中输入需要 runtime 命令入口和唯一终端输出所有者 |
| `niucode-agent/src/lib.rs` 的 approver 是同步回调，loop 借用可变 SessionLog | 不允许用第二个日志 writer 或阻塞审批桥接来绕开事件所有权 |
| `niucode-tools/src/lib.rs` 的 observed 是路径集合；write/edit 直接 fs::write | read-before-write 不等于内容未变化，需要版本观测和冲突结果 |
| bash 非零退出仍返回 Ok 文本，ToolResult.ok 表示调用路径成功 | 验证成功必须来自结构化退出状态，不能沿用绿色工具图标推断 |
| `goal.rs` evaluator 只读目标和 actor 最后汇报 | 本轮汇总不能把 evaluator 的 met 当作测试通过证据 |
| `.github/workflows/ci.yml` 只有 Ubuntu job；真实 Ghostty 验收缺失 | CI 模拟、Linux 实机、macOS 实机分别记录，不能互相替代 |

这些是源码检查结论，不表示已完成全量缺陷审计或跨平台运行验证。

## 实施边界与代码所有权

沿用现有 crate。下列文件名是建议落点，创建时再更新 project.json 的实际 owned paths，不预先把不存在的实现写成 active 模块。

| 边界 | 所有者及建议落点 | 最小职责 |
|---|---|---|
| 编辑状态 | CLI：新增 `composer.rs`；迁出 editor/inline 的重复部分 | 文本、字素边界、光标、撤销、草稿、历史；输入动作到状态变化 |
| 补全 | CLI：复用 slash registry，按需提取 `completion.rs` | slash/参数/skill/路径候选；不复制命令定义，不负责绘制 |
| 终端 | CLI：新增 `terminal.rs`，整合现有 guards | 唯一事件读取和输出所有者、能力检测、布局、模式恢复 |
| 视图 | CLI：tui/diff/review，必要时提取 `transcript.rs` | 事件到显示块；详情窗口；无 provider/tool 调用和日志写入 |
| 会话执行 | agent：新增 `runtime.rs`，收敛现有 run 入口 | Command/Event、执行与审批生命周期、队列、取消、唯一日志 writer |
| 上下文 | agent：现有 context.rs | 根据日志投影补充消息与请求顺序；保留 tool call/result 配对 |
| 文件与进程 | tools：现有 lib.rs/preview.rs，按职责提取私有模块 | 内容版本、预览绑定、受控写入、进程退出状态与进程组清理 |
| 审阅事实 | agent：必要时新增 `changes.rs` | 本轮基线与操作记录到改动/验证证据；CLI 只消费 |
| 持久类型 | core：event.rs | 仅增加恢复和审计确实需要的事件/字段；不引入编辑器、终端或调度器类型 |

不为这些边界另建通用框架、插件系统、daemon 或泛型 Frontend trait。CLI 与 TUI 是 runtime 的两个真实消费者；颜色、提示符、布局规则不进入 agent/core。

## 1. 统一编辑与终端呈现

### 编辑行为

- Enter 提交；Ctrl-J 始终换行；终端能区分 Shift-Enter 时同样换行。无法区分的键不能靠终端品牌猜测。
- Bracketed paste 保留换行，CRLF 规范化一次；粘贴内容中的 Enter、slash 和控制字符不能触发提交或本地命令。异常超大输入明确提示预算，不静默截断。
- 光标与删除以字素簇为单位；显示宽度与字素分段分开处理。优先使用专门库，不手写 Unicode 分段规则。
- 软换行和可视区滚动共享一个布局结果；上下移动保留目标列，首尾边界才切换历史；返回历史末端恢复未提交草稿。
- 撤销/重做、单词移动/删除、Home/End、历史搜索有一致语义；撤销一次粘贴恢复粘贴前状态。
- 补全基于光标处 token，候选可滚动，选择项始终可见；路径发现复用 ignore 规则，尊重嵌套 .gitignore；大仓库发现可取消，不阻塞按键循环。
- 草稿在当前进程内跨审批、详情窗口和取消保留。跨重启草稿恢复不是本轮承诺；不新增 draft.json。

### 渲染与终端所有权

- 主 transcript 只追加；输入、状态、候选属于一个受控活动区。临时详情/审批可进入 alternate screen，退出恢复输入与原生 scrollback。
- 只有 terminal owner 可以读取终端事件、设置模式和写交互终端。运行时、observer 和后台任务发送数据，不能自行 println/eprintln。
- 正文按稳定块增量输出；基本标题、列表、代码块和 diff 可读，控制序列统一清洗。已进入 scrollback 的历史不反复擦写来实现折叠。
- 输入、审批、详情视图是显式状态转换。守卫恢复的是进入前状态，避免嵌套 guard 退出时错误关闭仍需要的 raw/mouse/paste 模式。
- 读取事件可取消、线程/任务可 join；禁止遗留永久阻塞的 event::read 线程。绘制合并与背压有界，慢终端不能阻塞取消或无限积累 token delta。
- 光标查询有超时，查询响应与用户输入分流，失败时不吞键；能力检测集中，遵守 TERM/NO_COLOR/非 TTY。
- 降级共享编辑语义；不增加按终端名字复制的 editor。现有 Ghostty fallback 仅在真实回归证据通过后移除。
- 详情阅读期间继续接收运行事件；仅主屏暂停呈现，退出后有序输出积累内容。积累有预算，超出时从日志重建；取消不等待详情关闭。

## 2. SessionRuntime 与运行中纠偏

落地 ADR-0004 的进程内 Command/Event 边界，保留 exec/JSON 的既有语义。实现先明确状态转移，再接 UI，禁止通过共享可变 history、轮询文件或克隆 SessionLog writer 打补丁。

### 生命周期

| 输入/事件 | 行为 |
|---|---|
| 空闲提交 | 创建一个用户任务执行区间，日志记录开始边界，开始请求 |
| 运行中普通提交 | 原文和稳定消息 ID 先记日志，标记待接收 |
| 安全请求边界 | 当前 assistant 的 tool calls 都有结果（包括拒绝/取消）；按序注入补充，再构建下一请求 |
| 已接收 | 标记消息已纳入发起的请求，不表示模型已遵守，也不声称上游恰好收到一次 |
| 显式排队 | 独立任务按 FIFO 等当前任务结束；排队文本不提前影响当前任务上下文 |
| 当前响应准备结束时收到补充 | runtime 按命令顺序处理已接受消息，再决定结束或继续；不丢失尾部消息 |
| 审批 | 使用 request/call ID 关联，等待期间仍处理输入与取消；旧/重复答复不授权新操作 |
| 取消 | 停止当前请求/工具/子任务，清理进程组，保留已完成事实与草稿；待处理消息保持可见 |
| 恢复会话 | 从事件恢复待处理消息和执行状态；显示中断结果未知的调用，不自动重放有副作用的操作 |

- “用户任务”覆盖多次模型请求；不要重新解释现有 TurnEnd（目前每次响应记录 usage）的含义。新增任务边界只解决归属与恢复。
- 单一 runtime 拥有日志追加；在 provider、工具、审批等待期间也能接收控制命令。I/O future 返回结果供 runtime 追加事件，不与第二个 writer 竞争。
- 临时输入队列有上限；只有日志追加成功才能确认接受。重试和 reconnect 使用消息 ID 去重，不承诺模型请求 exactly-once。
- 队列、接收标记、任务结束/取消是日志事实；history、状态栏、队列列表是投影。游标、选择、刷新节流不落日志。
- 请求失败后补充保留在上下文，可随显式继续再次提交；恢复后的独立排队任务需要用户继续才执行，replay/fork 不执行工具。
- 模型、权限和会话切换仍按既有安全边界处理；运行中会话切换不偷偷迁移消息或扩大权限。审批时输入普通文字不自动代表允许。
- 取消不等于撤销文件改动；中途写入或日志追加失败时用“结果未知”呈现，不能补造成功，也不能自动重复执行。
- 新事件向后兼容读取旧日志；新语义由集中 projection 解释。增加字段有默认值，禁止不同消费者各自写一套队列恢复算法。

## 3. 并发编辑与审阅证据

### 文件修改

- 将 observed 路径集合升级为内容版本观测；不能仅依赖 mtime/文件大小。部分 read 不自动授权覆盖未展示的全部内容，明确 edit 与整文件 write 的前置条件。
- 为 write/edit 建立共享的 prepare/validate/apply 路径，预览与实际应用绑定同一旧内容/目标版本。审批后版本变化使该预览失效，需要重新读取与重新决策。
- 对新建、删除重建、重命名、symlink 目标变化、外部原地写入分别校验；不把目标突然不存在当作已获授权的新建文件。
- 写入错误不能静默截断旧文件；替换过程处理权限、可执行位、清理和失败恢复。逐平台测试支持的替换语义，不把 atomic rename 误写成跨编辑器的原子 compare-and-swap。
- 保留父/Worker 的写串行约束；内部锁不约束外部编辑器。共享工作区方案是乐观冲突检测，最终检查与写入之间的外部竞争仍有残余窗口。
- bash/扩展不是文件工具版本检查的例外实现，也不能被包装成具有相同保证。操作前后采集变化证据，发现冲突暂停后续受影响写入；不自动回滚用户修改。文件 watcher 只能提示变化，不能证明来源。
- 审计写入发生但结果未记日志的崩溃窗口；缺少证据则标记未知，不能推断文件当前状态就是 agent 成功执行的结果。

### 本轮基线与累计 diff

- 基线在用户任务开始、第一次工具副作用前采集，使用当时磁盘内容；不能用 HEAD 或 staged diff 代替，也不修改用户 index、stash 或已有未提交内容。
- 基线覆盖 tracked 与非忽略 untracked，记录内容、存在性和必要元数据；非 Git 仓库显式使用受预算约束的文件清单，不能宣称完整仓库覆盖。
- 基线扫描和内容读取有字节/文件/时间预算，可取消；对超限、二进制、忽略路径、大文件和扫描期间发生变化的文件显示覆盖范围/未知，不给虚假的完整 diff。
- shell 的写集合事先未知，任务开始基线用来识别最终净变化；文件工具操作记录用于补充因果证据。工作区净变化不自动等于 agent 改动。
- 持久审阅事实通过事件记录受预算约束的基线内容/变化与覆盖范围；缓存仅为可删除的派生加速。若完整内容未记录或超限，恢复后相应 diff 明确不可重建，不依赖隐藏 snapshot 数据库。
- 取消/失败后同样能审阅已记录改动。本轮内反复编辑显示最终净差异，并可定位操作记录；未知外部修改单独标识，不混入 agent 成果摘要。

### 验证结果

- 工具执行状态与命令退出状态分开：正常退出码、信号、超时、取消、基础设施错误均结构化记录。保持 tool call ID 关联；旧 ToolResult.ok 不静默改变语义。
- 界面“命令退出 0”仅证明该命令成功退出；只有明确选定的验收命令才能标为对应检查通过，不从任意 shell 文本或模型自述猜测测试成功。
- 每条验证证据关联命令、工作目录、call ID、任务与发生顺序。检查之后又修改相关工作区时标记结果可能过期，不能继续显示最终版本已验证。
- 完成卡分别显示修改文件、已执行检查、失败/未验证项与未知变化。无工具 evaluator 的 met 不是检查通过证据；本轮不扩展自主 goal 调度能力。

## Robust / clean 的审查门槛

1. 同一个编辑/候选/恢复规则只有一个实现；迁移时写清旧路径的删除点，002/003 完成后不长期维护两套编辑内核。
2. 终端品牌特判、新增环境开关、固定延迟、吞错误、全局可变状态都不是默认修复手段。兼容例外必须有最小复现、适用范围、回归用例与移除条件。
3. 事件写入、终端恢复、任务取消、线程回收的错误路径有明确所有者；不依靠 Drop 中不可观测的修补来伪造成功。
4. 所有异步等待可取消；输入、输出和工具结果队列有界；不持有会阻塞 UI 控制的锁等待人工审批。
5. 每次重构保持已有 CLI/JSON、权限、resume/fork/compaction 行为有回归证据。只因新功能需要而扩大 core，且在 ADR 中说明持久语义。
6. 默认切换必须同时包含调用方迁移、旧逻辑删除、文档和验证。测试通过后再扩展下一阶段，不能把多个未验证子系统一次性替换。
7. 不通过 mock 全部 I/O 来证明终端可靠；逻辑测试、PTY 和真实终端各证明自己的范围。
8. 每张实现卡评审最终 diff：重复状态是否消失、边界是否更小、失败是否可解释、取消是否完整、未知事实是否被错误美化。

## 后续与范围控制

后续独立里程碑：真实任务成功率/人工纠偏次数/时延与成本评测、长上下文质量、无人值守 goal 的独立证据验证。本轮不引入 Windows 一等支持、常驻全屏桌面、自动合并用户改动或通用多代理调度器。

架构决策见 ADR-0028；各卡片的验收是执行依据。本计划不以缺少真实终端环境为由跳过可独立完成的实现，也不把未验证的平台承诺写成 done。
